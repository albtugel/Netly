# Budget Service API

The machine-readable contract is [`budget-service.openapi.yaml`](budget-service.openapi.yaml) (OpenAPI 3.1). This page describes the same API for people: conventions, validation rules, the error format, and a request/response example for every operation.

All examples below are real responses from the service running against PostgreSQL, taken on 2026-09-26. Only the `Date`, `Server` and `Content-Length` headers are left out.

## Conventions

| Topic          | Rule                                                                                                   |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| Base URL       | `http://localhost:8082` under docker compose; every resource lives under `/api/v1`                     |
| Format         | JSON in both directions; keys in responses are sorted alphabetically                                   |
| Money          | JSON number, at most two decimal places (`119.88`), stored as `NUMERIC(12,2)`                          |
| Dates          | `YYYY-MM-DD` strings for calendar days; `createdAt` / `updatedAt` are ISO 8601 UTC timestamps          |
| Ids            | Lowercase UUIDs generated by the server                                                                |
| Ownership      | Every record belongs to the token's user; another user's record answers `404`, exactly like a missing one |
| Create         | `201 Created`, a `Location` header with the new record's path and the record in the body              |
| Update         | `PATCH` with any subset of fields; absent or `null` fields keep their value. The merged record is validated with the same rules as on create |
| Delete         | `204 No Content`; deleting again answers `404`                                                         |
| List           | `?limit=1..100` (default `50`) and `?offset=0..` (default `0`); oldest first; `total` counts all of the user's records |
| Read-only data | `id`, `createdAt`, `updatedAt` and the computed monthly figures; they are ignored if sent              |

## Authentication

Every `/api/v1` route needs `Authorization: Bearer <jwt>`. The token is HS256-signed with the `JWT_SECRET` shared with Profile Service (at least 32 bytes). It carries the user id in `sub` and an expiry in `exp`. Only `GET /health` is public.

Profile Service will issue tokens. Until then, mint a development token with the default compose secret:

```bash
TOKEN=$(scripts/dev-token.sh)                                        # random user, valid for 24 h
TOKEN=$(scripts/dev-token.sh 3f2a8c1e-7b4d-4e9a-b5c6-1d2e3f4a5b6c)   # a fixed user
```

## Resources and validation rules

Validation runs in two phases:

1. **Decoding.** The body must be JSON of the right shape: required fields present, correct JSON types, known enum values, real calendar dates. Decoding stops at the first problem, so this phase reports **one** field.
2. **Business rules.** Once the body decodes, every rule below is checked and **all** violations come back together.

### Subscription — `/api/v1/subscriptions`

| Field            | Type   | Required on create | Rule                                                      | Error codes                                   |
| ---------------- | ------ | ------------------ | --------------------------------------------------------- | --------------------------------------------- |
| `name`           | string | yes                | 1–100 characters after trimming surrounding whitespace    | `blank`, `too_long`                           |
| `price`          | money  | yes                | `> 0`, `≤ 1 000 000`, at most 2 decimals                  | `must_be_positive`, `too_large`, `too_precise` |
| `billingCycle`   | enum   | yes                | `weekly`, `monthly`, `quarterly`, `yearly`                | `invalid_value`                               |
| `nextChargeDate` | date   | yes                | valid `YYYY-MM-DD`                                        | `invalid_value`                               |
| `monthlyCost`    | money  | read-only          | `price` per month: weekly × 52 / 12, quarterly / 3, yearly / 12, rounded to cents | —                    |

### Debt — `/api/v1/debts`

| Field            | Type   | Required on create | Rule                                                                  | Error codes                                   |
| ---------------- | ------ | ------------------ | --------------------------------------------------------------------- | --------------------------------------------- |
| `creditor`       | string | yes                | 1–100 characters after trimming                                       | `blank`, `too_long`                           |
| `amount`         | money  | yes                | `> 0`, `≤ 100 000 000`, at most 2 decimals                            | `must_be_positive`, `too_large`, `too_precise` |
| `dueDate`        | date   | yes                | after today (UTC); checked only when the date is set or changed        | `invalid_value`, `must_be_in_future`          |
| `monthlyPayment` | money  | read-only          | `amount` / months left until `dueDate` (a started month counts, at least 1), rounded up to the cent | — |

Because the date rule applies only when the date changes, an overdue debt can still get a new amount or creditor.

### Goal — `/api/v1/goals`

| Field                         | Type    | Required on create    | Rule                                                           | Error codes                                   |
| ----------------------------- | ------- | --------------------- | -------------------------------------------------------------- | --------------------------------------------- |
| `name`                        | string  | yes                   | 1–100 characters after trimming                                | `blank`, `too_long`                           |
| `targetAmount`                | money   | yes                   | `> 0`, `≤ 100 000 000`, at most 2 decimals                     | `must_be_positive`, `too_large`, `too_precise` |
| `savedAmount`                 | money   | no, default `0`       | `≥ 0`, at most 2 decimals, `≤ targetAmount`                    | `must_not_be_negative`, `too_large`, `too_precise`, `exceeds_target` |
| `targetDate`                  | date    | yes                   | after today (UTC); checked only when set or changed             | `invalid_value`, `must_be_in_future`          |
| `priority`                    | integer | yes                   | 1–10, higher is more important                                 | `out_of_range`                                |
| `status`                      | enum    | no, default `active`  | `active`, `completed`, `archived`                              | `invalid_value`                               |
| `requiredMonthlyContribution` | money   | read-only             | (`targetAmount` − `savedAmount`) / months left; `0` once reached or not `active` | —                            |

`exceeds_target` compares two fields. It is skipped when either amount is already invalid on its own, so a field never gets two errors at once.

### Query and path parameters

| Parameter | Rule                  | Error codes                     |
| --------- | --------------------- | ------------------------------- |
| `limit`   | integer 1–100         | `invalid_type`, `out_of_range`  |
| `offset`  | integer ≥ 0           | `invalid_type`, `out_of_range`  |
| `{id}`    | UUID                  | `invalid_value`                 |

## Error format

Every error, including an unknown route, is `application/problem+json` as defined by [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457), with two extensions:

- `code`: stable machine-readable identifier; clients branch on it, not on `title` or `detail`.
- `errors`: present only for `validation_failed`, with one entry per invalid field (`field`, `code`, `message`).

`type` is always `about:blank`, so `title` is the status summary and `code` carries the specific meaning.

```json
{
  "code": "validation_failed",
  "detail": "2 fields are invalid",
  "errors": [
    { "code": "out_of_range", "field": "limit", "message": "Must be between 1 and 100" },
    { "code": "out_of_range", "field": "offset", "message": "Must be greater than or equal to 0" }
  ],
  "instance": "/api/v1/debts",
  "status": 422,
  "title": "Validation failed",
  "type": "about:blank"
}
```

| Status | `code`              | When                                                                                  |
| ------ | ------------------- | ------------------------------------------------------------------------------------- |
| 400    | `malformed_json`    | The body is not parseable JSON                                                        |
| 401    | `unauthorized`      | Missing token, wrong signature, expired token, or `sub` that is not a UUID            |
| 404    | `not_found`         | No such route, or no such record for this user                                        |
| 422    | `validation_failed` | Missing field, wrong JSON type, unknown enum value, invalid date, or a broken rule    |
| 500    | `internal_error`    | Anything unexpected; the cause is logged, the response says only "An unexpected error occurred" |

Field-level codes:

| `errors[].code`        | Meaning                                              |
| ---------------------- | ---------------------------------------------------- |
| `required`             | Field is missing or `null` on create                 |
| `invalid_type`         | Wrong JSON type, e.g. a string where a number is due |
| `invalid_value`        | Unknown enum value, impossible date, or non-UUID id  |
| `blank`                | Text is empty after trimming                         |
| `too_long`             | Text exceeds 100 characters                          |
| `must_be_positive`     | Amount must be greater than 0                        |
| `must_not_be_negative` | Amount must be 0 or more                             |
| `too_large`            | Amount above its maximum                             |
| `too_precise`          | More than 2 decimal places                           |
| `out_of_range`         | Integer outside its allowed range                    |
| `must_be_in_future`    | Date is today or earlier                             |
| `exceeds_target`       | `savedAmount` is greater than `targetAmount`         |

## Operations

`$TOKEN` comes from `scripts/dev-token.sh`, and `$BASE` is `http://localhost:8082`.

### Subscriptions

```bash
curl -X POST $BASE/api/v1/subscriptions \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "Netflix", "price": 119.88, "billingCycle": "yearly", "nextChargeDate": "2026-10-15"}'
```

## Error examples

Every error response has `Content-Type: application/problem+json`.

### 400 — body is not JSON

```bash
curl -X POST $BASE/api/v1/subscriptions -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" -d '{"name": "Netflix", "price": }'
```

```json
{
  "code": "malformed_json",
  "detail": "Request body is not valid JSON",
  "instance": "/api/v1/subscriptions",
  "status": 400,
  "title": "Malformed JSON",
  "type": "about:blank"
}
```

### 401 — missing, foreign or expired token

`curl $BASE/api/v1/subscriptions` with no `Authorization` header:

```json
{
  "code": "unauthorized",
  "detail": "Missing bearer token",
  "instance": "/api/v1/subscriptions",
  "status": 401,
  "title": "Unauthorized",
  "type": "about:blank"
}
```

A token signed with a different secret gives `"detail": "Invalid token"`. An expired one, e.g. `scripts/dev-token.sh <user> -60`, gives `"detail": "Token has expired"`.

### 404 — another user's record

A goal that exists but belongs to another user answers exactly like a missing one:

```json
{
  "code": "not_found",
  "detail": "Goal 8dc1e790-2c2c-4cb2-a270-7aa437877316 was not found",
  "instance": "/api/v1/goals/8dc1e790-2c2c-4cb2-a270-7aa437877316",
  "status": 404,
  "title": "Not found",
  "type": "about:blank"
}
```

An unknown route, e.g. `GET /api/v1/unknown`, answers `404` with `"detail": "Route not found"`.

### 422 — every broken rule at once

```bash
curl -X POST $BASE/api/v1/goals -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"name": "  ", "targetAmount": 100, "savedAmount": 150.555, "targetDate": "2020-01-01", "priority": 11}'
```

```json
{
  "code": "validation_failed",
  "detail": "4 fields are invalid",
  "errors": [
    { "code": "blank", "field": "name", "message": "Must not be blank" },
    { "code": "too_precise", "field": "savedAmount", "message": "Must have at most 2 decimal places" },
    { "code": "must_be_in_future", "field": "targetDate", "message": "Must be after 2026-09-26" },
    { "code": "out_of_range", "field": "priority", "message": "Must be between 1 and 10" }
  ],
  "instance": "/api/v1/goals",
  "status": 422,
  "title": "Validation failed",
  "type": "about:blank"
}
```

### 422 — decoding problems

These are reported one field at a time (see [Resources and validation rules](#resources-and-validation-rules)).

| Request body                                                                  | `errors`                                                                                   |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| `{"amount": 10, "dueDate": "2027-01-01"}` to `/debts`                         | `[{"code": "required", "field": "creditor", "message": "Field is required"}]`              |
| `{"creditor": "Friend", "amount": "a lot", "dueDate": "2027-01-01"}` to `/debts` | `[{"code": "invalid_type", "field": "amount", "message": "Expected number"}]`            |
| `{…, "status": "paused"}` to `/goals`                                         | `[{"code": "invalid_value", "field": "status", "message": "Must be one of: active, completed, archived"}]` |

### 422 — PATCH is checked against the stored record

The goal was created with `targetAmount: 5000`; the patch sends only `savedAmount`:

```bash
curl -X PATCH $BASE/api/v1/goals/8dc1e790-2c2c-4cb2-a270-7aa437877316 \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"savedAmount": 6000}'
```

```json
{
  "code": "validation_failed",
  "detail": "1 field is invalid",
  "errors": [
    { "code": "exceeds_target", "field": "savedAmount", "message": "Must not exceed targetAmount" }
  ],
  "instance": "/api/v1/goals/8dc1e790-2c2c-4cb2-a270-7aa437877316",
  "status": 422,
  "title": "Validation failed",
  "type": "about:blank"
}
```

### 422 — bad paging or id

`GET /api/v1/debts?limit=500&offset=-1` reports both parameters (see [Error format](#error-format)). `GET /api/v1/goals/not-a-uuid`:

```json
{
  "code": "validation_failed",
  "detail": "1 field is invalid",
  "errors": [
    { "code": "invalid_value", "field": "id", "message": "Must be a UUID" }
  ],
  "instance": "/api/v1/goals/not-a-uuid",
  "status": 422,
  "title": "Validation failed",
  "type": "about:blank"
}
```
